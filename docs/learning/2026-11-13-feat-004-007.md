## Concepts Defended
1. **Cross-OS text encodings (`cp1252` vs `UTF-8`) and BOM (`utf-8-sig`):**
   - Unlike .NET (which defaults to UTF-8 everywhere), Python's `subprocess.run(..., text=True)` and `sys.stdin` default to the OS locale encoding (`UTF-8` on macOS/Linux, `cp1252` on Windows).
   - Passing `encoding="utf-8"` forces UTF-8 across OSes; reading raw bytes via `sys.stdin.buffer.read().decode("utf-8-sig")` also strips the UTF-8 BOM (`\ufeff`) that Windows PowerShell 5.1 prepends on pipes (which would otherwise crash `json.loads`).
2. **`@pytest.fixture` (`tmp_path` → `gate_repo`) and test isolation:**
   - Whereas xUnit resolves test dependencies by **type** in the class constructor, `pytest` resolves fixtures by the **exact parameter name** (`tmp_path`, `gate_repo`); the `: Path` type annotation is only for `pyright`.
   - Running `stop_gate.py` in a throwaway Git repo (`gate_repo`) prevents the test from depending on the real repo's `git status` (which passed locally when dirty on the Mac, but failed on a clean CI checkout).
3. **`str.startswith(tuple)` and path-prefix boundary (`"tests/acceptance/"`):**
   - In Python, `str.startswith()` and `str.endswith()` natively accept a **`tuple` of strings** (`PROTECTED = ("tests/acceptance/", "evals/")`) as a shorthand for `any(path.startswith(p) for p in PROTECTED)`, but raise `TypeError` at runtime if given a `list` (`[...]`).
   - Including the trailing `/` in `"tests/acceptance/"` ensures a sibling file like `"tests/acceptance_helpers.py"` is not falsely treated as inside the `tests/acceptance/` directory.
