# Walking Skeleton (Slice A): Search End to End with Local Atlas and Fake AI Ports

## Goal
Deliver the thinnest end-to-end vertical slice of `POST /search` across `domain`, `application`, `infra` (MongoDB Atlas Local) and `api` (FastAPI), using deterministic fake `LanguageModel` and `Embedder` ports alongside a real `mongodb/mongodb-atlas-local:8.0` vector database seeded from spike 16's ~300 movie profiles, covering all five product response states, deterministic step-4 checks, the six deterministic CI evals, and the Atlas pre-filter and index-lifecycle verifications.

## Acceptance tests (written or approved by the owner)
- [ ] Given a seeded catalogue across ES/US/BO and a valid `POST /search` request (`text`, `country`, `providers`), when at least 5 streamable candidates match, then it returns HTTP 200 with `state="success"`, 5 movies streamable on the selected country+providers (P1), each with `title`, `year`, `runtime`, `poster_url`, `services`, `pitch` ($\le 350$ chars, P2), `tmdb_url`, and `availability_updated_at` (P6), plus top-level `attribution` (TMDB section-3 notice + JustWatch notice, P5) and `trace` (`timings_ms`, `tokens`, `cost_usd`) -> `tests/acceptance/test_walking_skeleton.py::test_search_returns_five_streamable_movies_with_pitches_attribution_and_freshness`
- [ ] Given a request where both UI fields and the extracted `QueryIntent` set constraints (`max_runtime`, `max_intensity`, `avoid`, `year_min`/`year_max`, `original_languages`), when `POST /search` runs, then the stricter limit applies (`min` for runtime/intensity, union for `avoid`), step 4 re-checks every constraint deterministically by value, and no returned movie violates any applied constraint (P3, US2) -> `tests/acceptance/test_walking_skeleton.py::test_search_enforces_merged_ui_and_intent_constraints_strictly`
- [ ] Given an `audience="kids"` or `audience="teens"` constraint in `QueryIntent` and movies with US certifications, ES-only certifications, and `null` certifications, when `POST /search` runs, then suitability follows architecture Q16 (`certification_us` first, else `certification_es`, else profile `intensity` and disallowed `content_warnings`) -> `tests/acceptance/test_walking_skeleton.py::test_search_enforces_audience_certification_and_profile_fallback_rule`
- [ ] Given a `POST /search` request with `exclude_ids` and multiple matching movies sharing a `collection_id`, when results are returned, then no movie in `exclude_ids` appears (US3) and at most one movie per non-null `collection_id` is selected (movies with `collection_id=None` are never deduplicated) -> `tests/acceptance/test_walking_skeleton.py::test_search_excludes_seen_ids_and_deduplicates_collections`
- [ ] Given a query whose `QueryIntent` includes `unmapped_constraints` (e.g. `["no spiders"]`) and narrow filters that leave fewer than 5 valid candidates after step 4, when `POST /search` runs, then it returns HTTP 200 with `state="partial"`, the matching movies ($< 5$), the partial-results note, and a note listing the unmapped constraints (`"We couldn't apply: no spiders"`, Q18) -> `tests/acceptance/test_walking_skeleton.py::test_search_partial_state_and_unmapped_constraints_note`
- [ ] Given the step-5 re-rank/pitch LLM call fails or still returns invalid output (invented ID, duplicate ID, wrong pick count, or pitch $> 350$ chars) after one retry, when `POST /search` runs, then it returns HTTP 200 with `state="results_without_pitches"`, up to 5 valid step-4 candidates ordered by score with `pitch=None`, and the pitches-unavailable note (plus the partial note if step 4 left $< 5$, Q8) -> `tests/acceptance/test_walking_skeleton.py::test_search_falls_back_to_results_without_pitches_when_rerank_llm_fails`
- [ ] Given an empty or $> 500$-character mood prompt (P4), an unsupported country, an empty `providers` list, or a provider ID not in that country's static list, when `POST /search` is called, then it returns HTTP 422 identifying the invalid field without calling the LLM or database -> `tests/acceptance/test_walking_skeleton.py::test_search_rejects_invalid_input_with_422`
- [ ] Given the step-2 `Understand` LLM call fails after one retry or the candidate search / repository raises an operational error, when `POST /search` is called, then it returns HTTP 503 with `state="service_unavailable"` and a clear try-again-later message, never empty or invented results (Q8) -> `tests/acceptance/test_walking_skeleton.py::test_search_returns_503_service_unavailable_when_understand_or_db_fails`
- [ ] Given the deterministic eval suite over representative search scenarios, when run in CI (`uv run poe check`), then 100% of responses pass P1 (availability), P3 (constraints as applied), P4 (input bounds), P2 pitch length ($\le 350$ chars), real catalogue IDs, and output schema validation -> `tests/acceptance/test_walking_skeleton.py::test_deterministic_evals_pass_at_100_percent`
- [ ] Given a pinned `mongodb/mongodb-atlas-local:8.0` container seeded with the ~300 spike-16 profiles and deterministic 384-d vectors (`@pytest.mark.integration`), when index create/update/drop and `$vectorSearch` (`limit=150`) run with the 5 previously tested filters (`streamable`, `runtime`, `_id` `$nin` on 5,000 IDs, `profile.intensity`, `profile.content_warnings`) plus `year` range, `original_language`, `certification_us`, `certification_es`, and the Q16 `audience` rule, then all supported pre-filters combine without `OperationFailure` on Mac and Windows (Q4), and if Atlas `$vectorSearch` cannot express the `$or` null-certification `audience` filter, `CandidateSearch` omits `audience` from the pre-filter and step 4 enforces it deterministically -> `tests/acceptance/test_walking_skeleton.py::test_atlas_local_index_lifecycle_and_all_vector_search_prefilters`

## Out of scope
- Real `fastembed` (`BAAI/bge-small-en-v1.5`) adapter, verifying `query_embed` instruction prefixing, and query-embedding latency measurement (split into proposed Slice B, `feat-028`).
- Real OpenAI `gpt-6-luna` Pydantic AI adapter, verifying `ModelRetry` feedback on the live model, live token/cost calculation, and end-to-end LLM latency (split into proposed Slice C, `feat-029`).
- Hybrid quality/era/popularity step-4 weights (until `feat-022`, step 4 orders valid candidates by vector similarity score).
- Genre, people, or content-in-search fields (investigated in spike `feat-026` Q7; start from the v1 `QueryIntent` and `Profile` mirror schema in ADR 0005).
- Full TMDB crawl/ingest pipeline and provider aliasing (`feat-020`).

## Design notes (with C# comparison)
- **3-way split of the walking skeleton (Checkpoint Finding 7, owner decision 2026-11-22):**
  - **Slice A (`feat-018`, this spec):** full vertical path from `POST /search` through `SearchMovies` to `mongodb-atlas-local` with deterministic fake `LanguageModel` and `Embedder` adapters, all 5 response states, step-4 checks, deterministic evals, and Atlas pre-filter/index verification.
  - **Slice B (`feat-028`, proposed):** real `fastembed` `Embedder` adapter in `infra`, verifying `query_embed` adds BGE's query instruction, embedding the ~300 seed profiles with `template(profile)`, and measuring cold/warm query-embedding latency.
  - **Slice C (`feat-029`, proposed):** real Pydantic AI + OpenAI `gpt-6-luna` `LanguageModel` adapter (`OpenAIChatModel`, `NativeOutput`, `reasoning_effort="none"`), verifying `ModelRetry` with error feedback on the real model, live cost in `trace`, and first end-to-end latency numbers (Q7).
- **Owner learning & code ownership (Checkpoint Finding 4, owner decision 2026-11-22):**
  - The agent writes the full slice first; afterwards the owner and agent run a `/defend` session on the walking skeleton and the owner refactors/extends a module.
- **Layers and ports (`domain` $\leftarrow$ `application` $\leftarrow$ `infra`, `api`):**
  - `domain`: closed-vocabulary `Literal` types and value objects (`Profile`, `Movie`, `QueryIntent`, `CandidateMovie`, `MoviePitch`, `SearchRequest`, `SearchResponse`, `SearchTrace`, `ResponseState`), static launch country/provider catalog (`ES`, `US`, `BO`), deterministic step-4 filter/check functions (including Q16 `audience` rule and `collection_id` deduplication), and `Protocol` ports (`CandidateSearch`, `MovieRepository`, `LanguageModel`, `Embedder`). In C#, `Protocol` is structural duck-typed `interface` (like TypeScript interfaces or Go interfaces) checked by pyright without requiring explicit inheritance.
  - `application`: `SearchMovies` use case orchestrating steps 1–7 (`Validate` $\rightarrow$ `Understand` $\rightarrow$ `Retrieve` $\rightarrow$ `Check & Rank` $\rightarrow$ `Re-rank & Pitch` $\rightarrow$ `Check Output` $\rightarrow$ `Respond`).
  - `infra`: `MongoMovieRepository` and `AtlasCandidateSearch` using `pymongo.AsyncMongoClient` (Motor is deprecated), index management helpers (`create_search_index`, `update_search_index`, `drop_search_index`), plus deterministic fake/in-memory adapters for fast CI tests and local seed loading from spike 16's committed `pool_b_profiles.jsonl` (re-fetching TMDB bundles only when `TMDB_API_KEY` is provided, and falling back to deterministic metadata + profile fixture data so tests never commit raw TMDB payloads or wait on TMDB's terms inquiry, Checkpoint Finding 1).
  - `api`: FastAPI `POST /search` endpoint using `Depends` (like ASP.NET Core DI service registration) and mapping domain/application states to HTTP `200` (`success`, `partial`, `results_without_pitches`), `422` (`invalid_input`), and `503` (`service_unavailable`).
- **Verification checklist from `docs/backlog.md` and Checkpoint Finding 2:**
  - Pin the local Atlas image to `mongodb/mongodb-atlas-local:8.0` (matching Atlas M0's MongoDB 8.0 instead of `latest` / 9.0).
  - Verify creating, updating, and dropping the vector search index from code without silencing errors.
  - Verify all 5 original pre-filters together with a 5,000-ID `_id` `$nin` exclusion list, plus the new v1 filter paths (`year`, `original_language`, `certification_us`, `certification_es`) and test whether Atlas `$vectorSearch` supports the `$or` null-certification `audience` pre-filter (falling back to step 4 if unsupported, ADR 0005).
  - Confirm `mongodb-atlas-local:8.0` runs `$vectorSearch` in the integration test on both Mac and Windows (Q4).
